# ฝึกพับกล่อง · TGAT2 มิติสัมพันธ์

เว็บไว้ฝึกโจทย์ "พับกล่อง" (แผ่นคลี่ลูกบาศก์) ของ TGAT2 แบบไม่ต้องนั่งมโนในหัวอย่างเดียว
ดูแผ่นคลี่ → เลือกกล่องที่คิดว่าถูก → แล้วกดเปิดโมเดล 3D ดูได้เลยว่าพับออกมาหน้าตาเป็นยังไง หมุนเทียบกับทุกตัวเลือกได้ด้วย

แถมมีบทเรียนทีละขั้น 3 สูตร (ห้องสี่ผนัง · ตัดไว · กลิ้งกล่อง) ที่อธิบายทุกขั้นเป็นภาพ 3 มิติ ฝึกจนเก็ตแล้วค่อยไปลุยโจทย์จริง

## เริ่มรัน

```bash
pnpm install
pnpm dev          # http://localhost:3000
pnpm test         # เทสเรขาคณิตการพับ + ตรวจไฟล์โจทย์ทุกไฟล์
pnpm typecheck    # tsrs
pnpm lint         # oxlint
pnpm format       # oxfmt
pnpm build
```

## Tech stack

โปรเจคนี้ตั้งใจเลือกของใหม่ ๆ เร็ว ๆ มาใช้ ลองแล้วชอบ

| ส่วน | ใช้อะไร | ทำไม |
| --- | --- | --- |
| แอป | TanStack Start + Router, React 19, Tailwind CSS 4 | SSR, file routes, แยก code ตาม route ให้เอง type-safe ทั้งเส้น (อาจไม่ได้ใหม่ขนาดนั้นแล้ว แต่ใช้ดีจริง) |
| Type check | `tsrs` | TypeScript checker ตัวใหม่ที่เร็วกว่า `tsc` เยอะ รอแป๊บเดียวจบ |
| Lint / Format | `oxlint` + `oxfmt` | ของตระกูล Oxc เขียนด้วย Rust ไว๊ไว แทน ESLint + Prettier ได้เลย config นิดเดียว |
| 3D | three.js ผ่าน `@react-three/fiber` + `@react-three/drei` (`CameraControls`) | แผ่นคลี่ก็คือต้นไม้ของบานพับนั่นแหละ แต่ละหน้าเป็น `group` ซ้อนกันแล้วหมุนรอบขอบของหน้าพ่อ เลยพับทั้งกล่องได้ด้วยค่าเดียว |
| แอนิเมชัน | `useFrame` + `MathUtils.damp` | ไม่ต้องลาก GSAP / Framer Motion มา และไม่ re-render React ทุกเฟรม (`frameloop="demand"` วาดเฉพาะตอนมีอะไรขยับ) |
| ภาพ 2D | SVG | แผ่นคลี่กับลูกบาศก์ไอโซเมตริกคมทุกขนาด หน้าตาเหมือนในข้อสอบ |
| โจทย์ | JSON + Zod | เช็กรูปแบบ แล้ว "พับจริง" หาคำตอบให้ตอนโหลดเลย |

### ทำไมไม่ใช้ UI lib (shadcn ฯลฯ)

ตั้งใจไม่ใช้เลย อยากให้เว็บเบา ลีน ๆ ไม่แบกของที่ไม่ได้ใช้
เว็บนี้ UI ไม่ได้เยอะขนาดนั้น ส่วนที่ต้องใช้ซ้ำก็ทำเป็นคอมโพเนนต์เองเฉพาะจุด (อย่าง `Skeleton` ใน `src/components/ui/`) ส่วน class ของ Tailwind เขียนตรง ๆ ที่ตัว element เลย ไม่ทำไฟล์ style กลาง แค่นั้นพอ
แล้วยุคนี้ให้ AI ช่วยเขียนคอมโพเนนต์เองก็ไวพอ ๆ กับไปลง lib อยู่แล้ว แถมได้ตรงกับที่อยากได้เป๊ะกว่า

### ทำไมยังไม่ลง skill ให้ AI

ตอนนี้ตั้งใจยังไม่ลง skill อะไรพิเศษให้ AI เพราะโปรเจคยังเล็กอยู่ และเวลาสั่งงานก็เขียน prompt ละเอียดคุมเองทุกครั้งอยู่แล้ว
ถ้าวันไหนโปรเจคใหญ่ขึ้นหรือเริ่มสั่งอะไรซ้ำ ๆ บ่อย ๆ ค่อยมาเพิ่มทีหลัง

### เรื่องอื่น ๆ ที่ควรรู้

- **three.js โหลดทีหลัง** — แยกเป็น chunk ที่โหลดเฉพาะตอนเปิดมุมมอง 3D (`LazyFoldStage`) หน้าแรกเลยโหลดไว
- **ความคืบหน้า** (ข้อที่ทำถูก ความแม่น กิจกรรม 7 วัน) เก็บไว้ในเบราว์เซอร์ผู้เรียนเท่านั้นผ่าน `localStorage` แล้วอ่านด้วย `useSyncExternalStore`
  ฝั่ง server ไม่รู้ประวัติอะไรเลย หน้าเลยโชว์ skeleton ไปก่อนจนกว่าจะ hydrate เสร็จ
- **ธีมสว่าง/มืด** ตามเครื่องไปก่อนจนกว่าผู้ใช้จะกดสลับเอง ค่าที่เลือกเก็บใน cookie `theme` ให้ server render ธีมถูกตั้งแต่แรก ไม่กะพริบ
  สีพื้นฐานใช้ token ตามบทบาท (`bg-surface`, `text-ink`, `border-line` …) ที่ประกาศไว้ใน `src/styles.css` ส่วนสีสถานะเขียน `emerald` / `amber` / `rose` ตรง ๆ คู่กับ `dark:`
  — อย่าไปใช้ `stone-*` / `white` ตรง ๆ ในคอมโพเนนต์นะ

## เพิ่มโจทย์

สร้างไฟล์ใหม่ใน `src/content/questions/` ชื่อไฟล์คือทั้งลำดับและ URL (เช่น `07-my-question.json` → `/questions/07-my-question`)
แนะนำให้ไปร่างในหน้า **สร้างโจทย์** (`/lab`) ก่อน มันโชว์ผลและตรวจให้สด ๆ

```json
{
  "title": "แถบคู่กับสี่เหลี่ยมทึบ",
  "difficulty": "easy",
  "layout": ["A...", "BCDE", ".F.."],
  "faces": {
    "A": [
      { "type": "rect", "x": 0, "y": 29, "w": 100, "h": 11 },
      { "type": "rect", "x": 0, "y": 60, "w": 100, "h": 11 }
    ],
    "B": [{ "type": "rect", "x": 0, "y": 50, "w": 50, "h": 50, "fill": "none" }],
    "C": [{ "type": "rect", "x": 25, "y": 25, "w": 50, "h": 50 }]
  },
  "choices": [
    { "top": "A", "left": { "face": "B", "rotate": 90 }, "right": "C" },
    { "top": "A", "left": "B", "right": "C" }
  ],
  "explanation": "ข้อความอธิบายหลังตรวจคำตอบ"
}
```

- **`layout`** วาดแผ่นคลี่เป็นแถวตัวอักษร หนึ่งตัวต่อหนึ่งหน้า (`A–Z`, `0–9`) ส่วน `.` คือช่องว่าง ต้องมี 6 หน้าที่พับเป็นลูกบาศก์ได้จริง
- **`faces`** ลายของแต่ละหน้าในกรอบ 100×100 (มุมซ้ายบน = 0,0 มองจากด้านนอกกล่อง) หน้าไหนไม่ใส่ก็คือหน้าว่าง
  รูปที่ใช้ได้: `rect {x,y,w,h}`, `circle {cx,cy,r}`, `polygon {points}`, `line {from,to}` และ `fill`: `"black"` (ค่าเริ่มต้น) / `"gray"` / `"none"`
- **`choices`** 2–5 ข้อ แต่ละข้อบอกว่าเห็นหน้าไหนด้าน `top`, `left`, `right` ใส่เป็น `"A"` หรือ `{ "face": "A", "rotate": 90 }` (องศาตามเข็มนาฬิกา)
  `rotate: 0` คือหน้าตั้งตรงเวลามองจากด้านนอก — ด้านบนวางเหมือนพับขึ้นมาจากหน้าด้านซ้าย
- **`ask`** `"possible"` (ค่าเริ่มต้น) ถามรูปที่พับได้ หรือ `"impossible"` ถามรูปที่พับไม่ได้
- **`difficulty`** `"easy"` / `"medium"` / `"hard"`, **`prompt`** (ไม่ใส่ก็ได้) ใช้แทนคำถามเริ่มต้น

**ไม่ต้องใส่คำตอบเอง** ระบบจะพับแผ่นคลี่แล้วลองจับลูกบาศก์ครบทั้ง 24 ท่า ดูว่าตัวเลือกไหนพับได้จริง
โดยเทียบ "หน้าตา" ของลาย (หน้าว่างใช้แทนกันได้ และลายที่หมุนแล้วเหมือนเดิมก็นับว่าเหมือน)
ถ้าโจทย์มีคำตอบไม่ใช่ 1 ข้อพอดี `pnpm test` จะไม่ผ่าน และหน้าโจทย์ก็โหลดไม่ขึ้น

## บทเรียน 3 สูตร

การ์ด "เริ่มฝึกทีละขั้น" ในหน้าแรกจะเปิดหน้าต่างเลือกวิธี (บนมือถือเป็น bottom sheet) แล้วพาไป `/learn/$methodId?step=n`
แต่ละขั้นมีภาพ 3 มิติที่เล่นเองเป็น "จังหวะ" (pose) บางขั้นมีตัวเลือกให้ลองตัดเอง ขั้นสุดท้ายคือโจทย์จริงจากคลัง

เนื้อหาอยู่ใน `src/content/methods/` เขียนเป็น TypeScript แต่ละขั้นมี `scene` = แผ่นคลี่ + ลำดับจังหวะ
แต่ละจังหวะบอกแค่สิ่งที่เปลี่ยนจากจังหวะก่อนหน้า (ยกเว้น `note` ที่ต้องเขียนทุกจังหวะ)

```ts
scene: {
  ...CROSS,                                   // แผ่นคลี่จาก nets.ts (layout + faces + anchor)
  poses: [
    { note: 'สีเดียวกัน = คู่ตรงข้าม', opposite: [['B', 'D'], ['C', 'E']] },
    { note: 'กลิ้ง A ไปต่อกับ D', move: { face: 'A', from: 'C', onto: 'D' } },
    { note: 'พับเป็นกล่อง', fold: 1, view: { top: 'A', left: 'D', right: 'E' } },
  ],
}
```

- **`fold`** `1` พับทุกบานพับ หรือ `{ B: 1, D: 1 }` พับเฉพาะหน้าที่ระบุ (นับจาก `anchor` ที่อยู่กับที่)
- **`move`** ตัดหน้า `face` ออกจาก `from` แล้วไปต่อกับ `onto` ตามขอบที่ชนกันจริงตอนพับ (หน้าที่ห้อยอยู่ย้ายตามไปด้วย ลายก็หมุนตาม)
- **`view`** จับกล่องให้เห็นหน้าเหล่านี้ด้านบน/ซ้าย/ขวา เหมือนรูปในตัวเลือก
- **`opposite`** / **`meet`** / **`paint`** / **`labels`** ระบายคู่ตรงข้าม, ขีดขอบที่ชนกัน, ระบายสีอิสระ, เขียนคำบนหน้า

ทุกอย่างที่พูดถึงเรขาคณิตจะถูกเช็กกับกล่องที่พับจริงตอนโหลด — บอกว่าตรงข้ามแต่จริง ๆ ไม่ใช่ บอกว่าขอบชนแต่ไม่ได้ชน
มุมมองที่ดันเป็นภาพสะท้อน หรือตัวเลือกตัวอย่างที่ `verdict` ไม่ตรงกับการพับจริง เจอแบบนี้ `pnpm test` ไม่ผ่านแน่นอน

## โครงสร้าง

```
src/cube/          โดเมนล้วน (ไม่มี React): geometry, art, การพับแผ่นคลี่ (net), การย้ายหน้าในแผ่นคลี่ (arrangement), การเทียบภาพ (view), schema ของโจทย์
src/lesson/        โดเมนของบทเรียน: scene (จังหวะภาพ 3 มิติที่ตรวจแล้ว) และ method (ขั้นตอน ตัวอย่าง โจทย์ฝึก)
src/content/       คลังโจทย์ JSON + ตัวโหลดที่ตรวจทุกไฟล์, methods/ เนื้อหาบทเรียน 3 สูตร
src/progress/      ประวัติการตอบ (localStorage) + สรุปความคืบหน้าสำหรับแดชบอร์ด
src/theme/         ธีมที่ผู้ใช้เลือก (cookie อ่านได้ทั้ง server และ browser)
src/components/    ui/ (คอมโพเนนต์กลาง), layout/ (แถบเมนู), dashboard/ (การ์ดหน้าแรก), quiz/ (หน้าทำโจทย์),
                   learn/ (หน้าต่างเลือกวิธีและหน้าบทเรียน), lab/ (หน้าสร้างโจทย์), cube/ (ภาพ SVG),
                   cube-3d/ (three.js ทั้งหมด: พับ เลื่อน กลิ้ง — ข้างนอกใช้ได้แค่ LazyFoldStage / LazyLessonStage)
src/routes/        / (แดชบอร์ด), /questions (คลังโจทย์), /questions/$questionId, /learn/$methodId, /lab
```

## แนวทางเขียนโค้ด

เป้าหมายคือโค้ดที่อ่านแล้วเข้าใจเลย review ง่าย เลยใช้กติกาชุดเดียวกันทั้งโปรเจค

**ขอบเขตของโฟลเดอร์**

- import ไปทางเดียว: `routes → components → progress / theme → content → lesson → cube` ห้ามย้อนกลับ
- `cube/` กับ `lesson/` ห้ามมี React, three.js หรือ DOM
- ทุกอย่างที่ใช้ three.js อยู่ใน `components/cube-3d/` ข้างนอกใช้ได้แค่ `LazyFoldStage` / `LazyLessonStage` three.js จะได้อยู่ใน chunk ที่โหลดทีหลังเสมอ
- ไฟล์ route มีแค่ `Route` กับคอมโพเนนต์ของหน้านั้น ชิ้นส่วนอื่นไปอยู่ใน `components/<หมวด>/`

**ไฟล์**

- คอมโพเนนต์ตั้งชื่อ `PascalCase.tsx` และ export คอมโพเนนต์เดียวที่ชื่อตรงกับไฟล์ ตัวช่วยที่ใช้แค่ในไฟล์นั้นเขียนไว้ข้างล่างได้
- ไฟล์อื่นเป็น `kebab-case.ts` ไฟล์ที่มีแค่ hook ตั้งชื่อ `use-*.ts` เทสวางไว้ข้างไฟล์ที่เทส (`*.test.ts`)
- ใช้ named export ทั้งหมด ยกเว้นไฟล์ที่โหลดผ่าน `React.lazy` ซึ่งต้องเป็น `export default`

**Styling**

- เขียน class ของ Tailwind ตรง ๆ ที่ `className` ซ้ำกันหลายที่ได้ ไม่ทำไฟล์หรือค่าคงที่ไว้แชร์ string ของ class (`pnpm format` เรียง class ให้เอง)
- ถ้าซ้ำกันทั้งหน้าตาและพฤติกรรม ก็ทำเป็นคอมโพเนนต์ไปเลย (อย่าง `Widget`, `MethodIcon`)
- ตารางที่เลือก class ตามค่าที่มี type (เช่น `Record<ChoiceState, string>`) ใช้ได้ แต่ให้อยู่ในไฟล์ของคอมโพเนนต์ที่ใช้เท่านั้น

**TypeScript**

- props ตัวเดียวเขียน type inline ได้ ตั้งแต่ 2 ตัวขึ้นไปใช้ `interface XxxProps` วางไว้เหนือคอมโพเนนต์
- `import type { ReactNode } from 'react'` ไม่ใช้ `React.ReactNode`
- ตาราง lookup เขียนเป็น `const X: Record<Union, T> = {…}` ให้ TypeScript เช็กว่าครบทุกค่า
- โค้ดแอปไม่ใช้ `any`, `as` (ยกเว้น `as const`) และ `!` ถ้า type ไม่พอให้แก้ type ที่ต้นทาง (ในเทสใช้ `!` กับ lookup ที่รู้ว่ามีแน่ ๆ ได้)

**React**

- คอมโพเนนต์รับข้อมูล ไม่รับ JSX ที่ประกอบมาแล้วหรือ render function ยกเว้น `children` กับ slot ที่ตั้งชื่อชัด ๆ (อย่าง `nav`)
- reset state ด้วย `key` ยกเว้นตรงที่จะทำให้ canvas 3D mount ใหม่
- `useMemo` / `useCallback` ใช้เฉพาะตอนที่ identity สำคัญ (deps ของ effect, three.js) หรือเป็นงานหนักจริง ๆ
- loader คืนแค่ค่าเล็ก ๆ อย่าง index เพราะมันถูกส่งไปกับหน้าเว็บด้วย แล้วให้หน้าไปหยิบข้อมูลเอง

**import** ใช้ `#/…` เวลาข้ามโฟลเดอร์ และ `./…` ในโฟลเดอร์เดียวกัน เรียงเป็น package → `#/` ที่ไม่ใช่ components → `#/components` → `./`
